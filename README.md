# 🎾 랠리보드 (RallyBoard)

STEP UP 테니스 2030 모임용 코트 일정·참석 관리 웹앱입니다.
카카오톡 오픈채팅방 대신 링크 하나로 코트 일정, 참석/대기, N빵, 공지, 랭킹, 회비, 멤버 관리를 할 수 있어요.

- **프론트/서버:** Next.js 16 (App Router, Server Actions) + Tailwind CSS 4
- **DB:** Supabase (Postgres). 모든 로직은 `public.rb_*` RPC 함수에 있어요.
- **배포:** Vercel (Hobby 무료) · 매일 09:00 KST Cron
- **알림:** Web Push (VAPID)

## 자주 고치는 곳

| 바꾸고 싶은 것 | 파일 |

| 상단 제목·슬로건, 배경 이미지 | `components/RallyApp.tsx` (`HERO`, `<h1>`) |

| 규칙(정원, 대기 승격, 회비 대상 등) | `supabase/schema.sql`의 해당 함수 → Supabase SQL Editor에서 실행 |

## 로컬에서 실행

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev                  # http://localhost:3000
```

## 처음부터 새로 세팅하기

1. **Supabase:** 새 프로젝트 생성 → SQL Editor에 `supabase/schema.sql` 전체를 붙여넣고 실행
   (`CHANGE_ME_TO_PUSH_SECRET`은 직접 만든 PUSH_SECRET 값으로 바꾸기)
2. **VAPID 키:** `npx web-push generate-vapid-keys` → 공개키는 코드 안 `VAPID_PUBLIC` 상수 모두, 개인키는 환경변수로
3. **Vercel:** 이 폴더를 GitHub에 올리고 Vercel에서 Import → `.env.example`의 환경변수 입력 → Deploy
4. 사이트에 **가장 먼저 가입한 사람이 방장**이 돼요.

## 2026-10-29 가입·정모 작성 보완

- 가입·로그인 입력과 정모 작성/수정 초안을 브라우저 탭의 sessionStorage에 최대 24시간 저장합니다. 닫기와 새로고침 후 복원하며, 성공한 제출이나 입력 초기화 시 지웁니다. PIN은 저장하지 않습니다. 정모 초안은 회원과 일정별로 구분합니다.
- 작성창 바깥을 눌렀다가 바깥에서 놓을 때만 닫습니다. 창 안에서 시작한 드래그는 바깥에서 마우스를 놓아도 작성창을 닫지 않습니다.
- 가입 버튼은 미완성 상태에서도 눌러볼 수 있고, 누르면 누락·오입력 항목 목록과 각 입력칸의 안내를 표시합니다.
- 새 정모의 코트명은 비워두고 예시를 placeholder로 표시합니다. 제목은 날짜·요일·코트명으로 자동 생성하며 별도 제목 입력칸은 제거했습니다. 추가 안내는 메모에 입력합니다.
- 카카오페이 안내는 첨부 화면을 가공한 5단계 이미지입니다. 원본 대신 계좌·잔액·얼굴·QR·주변 화면을 가린 사본만 `public/guides/kakaopay/`에서 제공합니다. 내장 image_gen으로 편집했으며 프롬프트는 `scripts/kakaopay-guide-prompts.json`에 있습니다.
- 개발 서버는 `allowedDevOrigins`에 회사 PC의 `172.16.15.20`과 로컬 테스트용 `127.0.0.1`을 허용합니다. IP가 바뀌면 `next.config.mjs`를 수정하고 개발 서버를 다시 시작하세요.
- 회사 IP의 HTTP 개발 환경에서 로그인 쿠키를 사용할 수 있도록 개발 중에만 Secure를 해제합니다. 배포 환경은 Secure 쿠키를 유지하므로 HTTPS로 접속해야 합니다.

이번 변경에는 추가 DB SQL 적용이 필요하지 않습니다. 개발 서버를 실행한 PC와 같은 네트워크의 기기에서 `http://172.16.15.20:3000/`으로 접속합니다. 다른 기기의 `localhost`는 그 기기 자신을 가리킵니다.

## 2026-10-27 요청사항 반영

테니스 프로젝트의 「랠리보드 요청사항 정리」에 정리된 확정 규칙을 반영했습니다. 결제업체는 미정이므로 실제 통장 내역을 호스트·운영진이 확인하는 방식입니다.

| 기능 | 사용 방법 |
|---|---|
| 지하철역 닉네임 | 가입 시 역 이름 입력, 기존 회원은 프로필 → 내 지하철역에서 변경 |
| 유료 정모 신청 | 입금 대기 → 실제 입금 → 내 정모 / 입금·벌칙에서 확인 요청 → 호스트·운영진 확인 → 참석 확정 |
| 자리 대기 | 정원이 차면 자리 대기. 미입금자는 빈자리가 나도 입금 확인 전 확정되지 않음 |
| 참가 관리 | 정모 카드 → 참가·입금·지각·후기 관리. 본인 입금은 다른 운영진 확인 필요 |
| 내 정모 | 예정 정모와 입금 대기·참석 확정·자리 대기 필터, 지난 정모, 참가비·벌칙, 알림함 |
| 취소 | 사전 호스트 연락 및 대참자 확보 안내. 4일 이상 전 무료, 3~2일 전 2,000원, 전날 5,000원, 당일 10,000원 또는 당근리뷰 |
| 지각·불참 | 15분 5,000원, 30분 10,000원, 무단 불참 15,000원 또는 당근리뷰. 기존 노쇼 버튼에도 같은 규칙 적용 |
| 미납 제한 | 지각·불참 미납 등록 시 향후 신청 자동 취소·참가 차단. 운영진이 미납 건 전부 확인한 뒤 해제. 기존 신청은 자동 복원하지 않음 |
| 대참·환불 | 확정된 대참자를 취소 내역에 연결. 참가비는 환불 확인 대기로 보존하며 실제 환불 후 확인 근거 기록 |
| NTRP | 프로필에서 요청 → 운영 / 정모 운영에서 승인·반려. 운영진만 변경 가능 |
| 후기 | 종료된 정모의 호스트가 작성. 확정 참가자 중 노쇼를 제외한 명단 기록, 참가자는 지난 내 정모에서 조회 |
| 회비 면제 | 가입 월 말일−10일부터 말일까지 가입, 운영진, 해당 월 종료된 정모 호스트 3회 이상, 기존 1년권 기간 |
| 기존 1년권 | 운영 / 정모 운영 / 회비 면제에서 실제 구매 근거와 시작월·종료월 직접 등록 |

참가비 표시·입금 기록 금액은 `(코트비 + 볼비) ÷ 정원`을 100원 단위로 올림한 값으로 통일했습니다. 신청·입금 내역이 있는 동안 1인 금액을 바꾸는 수정은 차단합니다. 입금 대기 자체가 좌석을 보장하지 않으므로 입금 전 호스트에게 자리와 금액을 확인해야 합니다.

### 기존 서비스 DB 적용

코드 파일만 바꾸거나 서버를 다시 켜도 Supabase의 함수·테이블은 바뀌지 않습니다.

1. Supabase 프로젝트에서 DB 백업을 확보하고 **SQL Editor**를 엽니다.
2. `supabase/migrations/20261027_club_requests.sql` 전체를 실행합니다. 기존 서비스에는 이 변경 파일을 사용하세요. `schema.sql`은 새 DB용 전체 정의입니다.
3. 실행 성공 후 앱을 새로고침합니다. DB 적용 전에는 상단 안내를 표시하고 새 규칙이 필요한 참가 신청·취소를 막습니다.
4. **앞으로 열리는 유료 정모의 기존 참석 확정자 중 입금 확인 기록이 없는 회원은 입금 대기로 전환됩니다.** 해당 회원에게 앱 알림을 남깁니다. 이미 낸 돈을 다시 받는 것이 아니라 호스트가 기존 실제 입금 내역을 확인하는 절차입니다. 과거 출석·랭킹 기록은 전환하지 않습니다.
5. 기존 회원의 지하철역과 1년권 적용 기간을 확인하고 입력합니다.

변경 파일은 하나의 트랜잭션으로 실행되며 재실행해도 확인된 입금이나 알림을 중복 처리하지 않습니다. 새 기능의 SQL을 수정하면 `npm run schema:sync`로 전체 `schema.sql`에도 반영하세요.

### 아직 확정하거나 연결해야 하는 사항

- 결제업체, 가상계좌, 자동 입금 조회, 실제 환불 송금, 호스트 자동 정산은 **미연동**입니다. 확인 버튼은 입출금 기록을 남기며 돈을 송금하지 않습니다.
- 입금 기한, 자리 보장 시간, 대기자 입금 시점의 자동 처리, 환불·이월 금액 기준은 미확정입니다. 자동 기한 취소나 환불 금액 계산을 추가하지 않았습니다.
- 후기와 랭킹의 연결 규칙은 미확정이라 기존 랭킹 계산을 유지합니다.
- 회비 면제 대상이 이미 납부한 회비는 자동 환불하지 않고 운영 화면에 확인 대상으로 표시합니다.
- 앱 알림함은 DB에 저장됩니다. 휴대폰 푸시는 별도로 `PUSH_SECRET`, `VAPID_PRIVATE_KEY`, 구독 허용이 필요하며 정기 재시도에는 `CRON_SECRET`도 필요합니다. 키가 없으면 앱 알림함만 동작합니다.
- 카카오페이 링크의 유효성은 링크 발급자가 확인해야 합니다. 기존 링크가 외부에서 404를 반환하는 문제는 수동 입금 확인 기능을 추가해도 해결되지 않습니다. 유효한 링크나 계좌 정보를 정모에 입력해야 합니다.

### 검증

```bash
npm run build
# fresh local PostgreSQL DB에 schema.sql을 먼저 적용한 후 실행
npm run test:club
```

통합 검증은 `127.0.0.1`의 전용 `rally_*_test` DB에서만 실행하며 기존 회원이 있는 DB에서는 시작하지 않습니다. Windows 기본값은 PostgreSQL 18, 포트 55432, 사용자 `rally_audit`, DB `rally_requests_test`입니다. `TEST_PSQL`, `TEST_PGPORT`, `TEST_PGUSER`, `TEST_DATABASE`로 로컬 테스트 환경을 지정할 수 있습니다. 새 클러스터는 `anon`, `authenticated` 역할을 만든 뒤 스키마를 적용합니다.

입금 확인과 권한, 동시 정원 배정, 취소 날짜 경계, 미납 제한·해제, 기존 출석 버튼, 알림 재시도, NTRP, 후기, 회비 면제 날짜, 기존 데이터 전환 및 재실행을 확인합니다. 실제 금융 거래·실기기 푸시 전달을 검사하는 테스트는 아닙니다.

## 보안 메모

- 코드에 들어 있는 Supabase 키는 **publishable(공개용) 키**라서 공개돼도 괜찮아요. DB 테이블은 막혀 있고 `rb_*` 함수만 열려 있어요.
- `PUSH_SECRET`, `VAPID_PRIVATE_KEY`, `CRON_SECRET`, Supabase 비밀키는 **절대 코드나 저장소에 올리지 마세요.** Vercel 환경변수에만 넣어요.
